# Deployment & CI/CD

All client websites and platforms are deployed using automated GitHub Actions pipelines and edge-rendered environments on Vercel.

## Continuous Integration Pipeline

Every push triggers the following automated stages in parallel:

```
Push to branch
├── Lint & Typecheck (eslint, tsc)
├── Component & Visual Tests (vitest)
├── Lighthouse Performance Checks
└── Ephemeral Staging URL Generation
```

## Deployment Environments

We run three tier environments:

1. **Preview**: Automatically generated ephemeral preview URLs for every pull request, allowing designers and clients to preview revisions instantly.
2. **Staging**: Internal staging server (`staging.client-domain.com`) used for end-to-end integration and client approvals.
3. **Production**: Live production domain (`www.client-domain.com`) served via Cloudflare CDN with automated SSL certificates.

<Callout type="warn">
Never connect a live client production domain until DNS TTL has been lowered to 300 seconds and SSL verification is completed.
</Callout>

## Rollback Procedures

If an unexpected regression is detected after production release, deployments can be instantly reverted within 10 seconds via Vercel instant rollback:

```bash
vercel rollback [deployment-url]
```
