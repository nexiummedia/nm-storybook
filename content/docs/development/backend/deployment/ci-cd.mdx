# CI/CD Pipelines

Continuous Integration and Continuous Deployment (CI/CD) pipelines enforce software quality, run automated test suites, build immutable container artifacts, and deploy services without manual developer intervention.

At Nexium Media, all CI/CD pipelines run on **GitHub Actions**.

---

## 1. Quality Gates Pipeline

Before any pull request can be merged into `develop` or `main`, the branch must pass three automated pipeline checks:

1. **Linting & Code Formatting**: Ensures style adherence (`eslint` / `ruff`).
2. **Type Checking**: Validates static types with zero errors (`tsc --noEmit` / `mypy`).
3. **Automated Test Suites**: Executes unit and integration tests with coverage reporting.

### Node.js (Express) Pull Request Workflow

```yaml title=".github/workflows/node-ci.yml"
name: Node.js Backend CI

on:
  pull_request:
    branches: [main, develop]
  push:
    branches: [main, develop]

jobs:
  test:
    name: Lint, Typecheck & Test
    runs-on: ubuntu-latest

    services:
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_USER: postgres
          POSTGRES_PASSWORD: testpassword
          POSTGRES_DB: nexium_test
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - name: Checkout Source Code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: Install Dependencies
        run: npm ci

      - name: Code Formatting & Lint Check
        run: npm run lint

      - name: Static Type Verification
        run: npm run typecheck

      - name: Run Database Migrations
        env:
          DATABASE_URL: "postgresql://postgres:testpassword@localhost:5432/nexium_test?schema=public"
        run: npx prisma migrate deploy

      - name: Execute Jest Test Suite
        env:
          DATABASE_URL: "postgresql://postgres:testpassword@localhost:5432/nexium_test?schema=public"
          JWT_SECRET: "test_secret_must_be_minimum_32_characters_long"
        run: npm test -- --coverage
```

### Python (FastAPI) Pull Request Workflow

```yaml title=".github/workflows/python-ci.yml"
name: Python FastAPI CI

on:
  pull_request:
    branches: [main, develop]
  push:
    branches: [main, develop]

jobs:
  validate:
    name: Lint, Mypy & Pytest
    runs-on: ubuntu-latest

    services:
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_USER: postgres
          POSTGRES_PASSWORD: testpassword
          POSTGRES_DB: nexium_test
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Setup Python 3.12
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'
          cache: 'pip'

      - name: Install Dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt
          pip install ruff mypy pytest pytest-asyncio pytest-cov httpx

      - name: Run Ruff Lint & Format Check
        run: ruff check .

      - name: Run Mypy Type Analysis
        run: mypy app

      - name: Run Pytest Test Suite
        env:
          DATABASE_URL: "postgresql+asyncpg://postgres:testpassword@localhost:5432/nexium_test"
          JWT_SECRET_KEY: "test_secret_key_must_be_minimum_32_chars_long"
        run: pytest --cov=app --cov-report=term-missing
```

## 2. Docker Image Build & Container Registry Push

Upon merging code into `main`, GitHub Actions builds the multi-stage Docker image and publishes it to Amazon Elastic Container Registry (ECR) or GitHub Container Registry (GHCR):

```yaml title=".github/workflows/deploy.yml"
name: Build & Push Image

on:
  push:
    branches: [main]

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Login to GitHub Container Registry
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Extract Metadata (Git SHA Tag)
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ghcr.io/${{ github.repository }}
          tags: |
            type=sha,format=long
            type=raw,value=latest

      - name: Build and Push Docker Image
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
```

<Callout type="tip">
**Image Tagging Policy**: Never deploy images tagged as `latest` to production. Production deployments must reference the immutable Git commit SHA tag (e.g. `ghcr.io/nexium/api:sha-a8f4c29`). This guarantees instant, reliable rollbacks if issues arise.
</Callout>

## 3. Rollback Procedures

If an anomalous error rate or critical bug is detected in production after deployment:

1. **Immediate Rolling Rollback**: Trigger the rollback workflow in GitHub Actions or re-apply the previous known stable Kubernetes deployment manifest:
   ```bash
   # Roll back to the previous deployment revision in Kubernetes
   kubectl rollout undo deployment/nexium-api -n production
   ```
2. **Verify Pod Status & Logs**: Check rollout progress and health check responses:
   ```bash
   kubectl rollout status deployment/nexium-api -n production
   ```
3. **Database Migration Rollbacks**: If the failed release included database migrations, evaluate if backward-compatible migrations require manual `prisma migrate resolve` or `alembic downgrade -1`.
