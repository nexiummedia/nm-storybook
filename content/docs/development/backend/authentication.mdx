# Authentication & Security

Security and client data confidentiality are paramount. All requests against protected Nexium Media APIs require cryptographic verification.

## Authentication Mechanisms

1. **API Keys**: Used for server-to-server integration between client websites and our CRM. Keys begin with prefix `nexium_live_` or `nexium_test_`.
2. **Bearer JWT Tokens**: Used for authenticated client portal and admin sessions.

## Making an Authenticated Request

Provide your API key or Bearer token via the `Authorization` header:

```bash
curl -X GET "https://api.nexiummedia.com/v1/campaigns" \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json"
```

<Callout type="warn">
Never transmit authorization tokens in URL query parameters. Query parameters are logged in load balancers and browser histories.
</Callout>

## Role-Based Access Control (RBAC)

User permissions are evaluated using four hierarchical roles:

- **Client Viewer**: Read-only access to campaign analytics, SEO audit reports, and invoices.
- **Client Manager**: Can submit change requests and review staging mockups.
- **Agency Developer**: Full engineering access to repositories, deployments, and staging servers.
- **Agency Admin**: Full administrative governance, financial billing, and token generation rights.
