Input validation is the primary line of defense against injection exploits, data corruption, and Denial of Service (DoS) attacks. At Nexium Media, we enforce a strict rule: **all input is guilty until proven innocent**.

---

## 1. Injection Attack Vectors & Mitigations

### 1. SQL Injection (SQLi)
- **The Threat**: Attackers append malicious SQL statements to unescaped query strings (e.g. `' OR '1'='1`).
- **Nexium Mitigation**: Always use Prisma ORM or SQLAlchemy with **parameterized queries**. Never use raw SQL string interpolation (`f"SELECT * FROM users WHERE email = '{email}'"`).

```ts
// ❌ CRITICAL VULNERABILITY: Raw string interpolation
await prisma.$queryRawUnsafe(`SELECT * FROM users WHERE email = '${req.body.email}'`);

// ✅ SAFE: Parameterized query automatically escapes inputs
await prisma.$queryRaw`SELECT * FROM users WHERE email = ${req.body.email}`;
```

### 2. NoSQL Injection
- **The Threat**: Attackers pass MongoDB query operators (`{"$gt": ""}`) in place of string inputs to bypass password checks.
- **Nexium Mitigation**: Enforce strict schema types with Zod/Pydantic so inputs must be literal primitive strings, rejecting raw JSON objects. Disable `$where` JavaScript evaluation in MongoDB server configurations.

### 3. Command Injection
- **The Threat**: Passing user input into OS shell execution (`child_process.exec` or Python `os.system`).
- **Nexium Mitigation**: Prohibit `child_process.exec` and `shell=True`. If process execution is mandatory, use `execFile` with an explicit arguments array:

```ts
import { execFile } from 'node:child_process';

// ✅ SAFE: Arguments passed as discrete array elements; shell parsing disabled
execFile('/usr/bin/convert', [inputPath, '-resize', '200x200', outputPath], (error) => {
  // handle result
});
```

## 2. Mass Assignment Prevention (`.strict()`)

Mass assignment vulnerabilities occur when a user payload contains unexpected administrative properties that are written directly to the database:

```ts title="Mass Assignment Exploit"
// Attacker sends: { "fullName": "Alex", "role": "SUPER_ADMIN" }
// ❌ WRONG: Writing raw body directly to database
await prisma.user.update({
  where: { id: userId },
  data: req.body, // Attacker escalates privileges to SUPER_ADMIN!
});
```

### The Solution: Strict Zod Schemas

```ts title="src/validators/user.validator.ts"
import { z } from 'zod';

export const updateUserProfileSchema = z
  .object({
    fullName: z.string().min(2).max(100),
    bio: z.string().max(500).optional(),
  })
  .strict(); // Rejects any payload containing unexpected fields (like 'role') with 422!
```

In FastAPI / Pydantic v2:
```python
from pydantic import BaseModel, ConfigDict

class UserProfileUpdateSchema(BaseModel):
    full_name: str
    bio: str | None = None

    model_config = ConfigDict(extra="forbid") # Rejects extra attributes with 422
```

## 3. File Upload Validation: Inspecting Magic Bytes

Attackers frequently bypass file extension checks by renaming a malicious executable or PHP script to `malicious.png`. Inspect the **file magic bytes** (file signature) on the binary buffer:

### Node.js: `file-type` Inspection

```ts title="src/utils/fileValidation.ts"
import { fileTypeFromBuffer } from 'file-type';
import { AppError } from './appError.js';

const ALLOWED_MIME_TYPES = ['image/jpeg', 'image/png', 'image/webp', 'application/pdf'];

export const validateUploadedBuffer = async (buffer: Buffer): Promise<string> => {
  const detected = await fileTypeFromBuffer(buffer);

  if (!detected || !ALLOWED_MIME_TYPES.includes(detected.mime)) {
    throw new AppError(
      `File content verification failed. Detected: ${detected?.mime ?? 'unknown'}`,
      400,
      'INVALID_FILE_SIGNATURE'
    );
  }

  return detected.mime;
};
```

## 4. Preventing Payload Denial of Service (DoS)

Malicious clients can crash servers by sending gigantic JSON bodies or nested objects that overwhelm parsing engines.

1. **Body Size Limits**:
   ```ts
   // Cap JSON bodies at 10 Megabytes
   app.use(express.json({ limit: '10mb' }));
   ```
2. **String Length Caps**: Never define unbounded strings in validation schemas. Always specify `min_length` and `max_length`.
