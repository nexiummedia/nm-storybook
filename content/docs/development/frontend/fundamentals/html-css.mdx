Delivering robust user interfaces begins with semantic HTML and modern CSS. Correct markup establishes the accessibility tree, optimizes search engine indexing, and ensures resilience across devices, while clean CSS provides performant layouts without relying on heavy JavaScript execution.

This guide details Nexium Media's standards for semantic document structure, accessible form construction, Flexbox and Grid layouts, CSS specificity, and cascade layers.

## Semantic HTML & Document Architecture

Semantic elements convey meaning to assistive technologies (screen readers, braille displays) and search engine crawlers. Generic `<div>` elements convey no semantic meaning and must never replace native structural landmarks.

### Landmark Hierarchy

Every web application shell must provide clear landmark regions:

```html
<!-- Canonical Document Landmark Structure -->
<header role="banner" class="site-header">
  <a href="#main-content" class="skip-link">Skip to main content</a>
  <nav aria-label="Primary Navigation">
    <ul>
      <li><a href="/dashboard">Dashboard</a></li>
      <li><a href="/campaigns">Campaigns</a></li>
      <li><a href="/reports">Reports</a></li>
    </ul>
  </nav>
</header>

<main id="main-content" class="main-layout">
  <header class="page-header">
    <h1>Quarterly Performance Analytics</h1>
  </header>

  <article class="metric-card">
    <h2>Conversion Velocity</h2>
    <p>Detailed performance metrics...</p>
  </article>

  <aside aria-label="Contextual Help" class="sidebar-help">
    <h3>Related Documentation</h3>
    <p>Help articles and guidance...</p>
  </aside>
</main>

<footer role="contentinfo" class="site-footer">
  <p>&copy; 2026 Nexium Media Group. All rights reserved.</p>
</footer>
```

### Semantic Element Rules

| Element | Intended Usage | Anti-Pattern to Avoid |
| :--- | :--- | :--- |
| `<main>` | The dominant, non-repeated content of the document. Exactly one per page. | Nesting `<main>` inside `<header>`, `<footer>`, or `<nav>`. |
| `<article>` | Self-contained composition that makes sense independently (e.g., blog post, product card, tweet). | Using `<article>` merely as a styled wrapper box. |
| `<section>` | Thematic grouping of content, typically with a heading (`<h2>`–`<h6>`). | Using `<section>` purely for CSS styling or background colors. |
| `<nav>` | Major navigational blocks (primary navigation, breadcrumbs, pagination). | Wrapping every single hyperlink inside a `<nav>`. |
| `<aside>` | Content tangentially related to the surrounding content (callouts, sidebars, glossaries). | Placing primary core content inside `<aside>`. |

<Callout type="warning">
Never skip heading levels (e.g., jumping from `<h1>` directly to `<h3>`). Screen reader users rely on hierarchical heading trees to skim content.
</Callout>

## Accessible Forms Architecture

Forms represent the primary interaction layer between users and Nexium applications. They must be completely keyboard operable and explicitly mapped to the accessibility tree.

```html
<!-- Accessible Form Pattern -->
<form novalidate class="form-container">
  <fieldset class="form-group">
    <legend class="legend-title">Account Security Configuration</legend>

    <!-- Text Input with Explicit Labeling and Validation State -->
    <div class="field-item">
      <label for="work-email" class="field-label">
        Work Email Address <span aria-hidden="true">*</span>
      </label>
      <input
        type="email"
        id="work-email"
        name="workEmail"
        required
        aria-required="true"
        aria-invalid="true"
        aria-describedby="email-error email-hint"
        class="input-control border-red-500"
      />
      <p id="email-hint" class="field-hint">Must be your corporate @nexiummedia.com email.</p>
      <p id="email-error" role="alert" class="field-error text-red-600">
        Please enter a valid corporate email address.
      </p>
    </div>

    <!-- Radio Group inside Sub-Fieldset -->
    <fieldset class="field-item">
      <legend class="field-label">Multi-Factor Authentication Method</legend>
      <div class="radio-options">
        <label>
          <input type="radio" name="mfa" value="app" checked />
          Authenticator Application (TOTP)
        </label>
        <label>
          <input type="radio" name="mfa" value="fido" />
          Hardware Security Key (FIDO2 / WebAuthn)
        </label>
      </div>
    </fieldset>
  </fieldset>

  <button type="submit" class="btn-primary">Save Preferences</button>
</form>
```

<Callout type="tip">
Always link validation error text to its input using `aria-describedby` matching the error element's `id`. When an error is present, set `aria-invalid="true"`.
</Callout>

## CSS Box Model Deep Dive

Every HTML element generates a rectangular box composed of four concentric layers:

1. **Content**: The text, image, or child elements.
2. **Padding**: Transparent space clearing the area around the content.
3. **Border**: The stroke around the padding.
4. **Margin**: Transparent clearance separating the box from its siblings.

```css
/* Universal Box Sizing Reset - Mandatory in all Nexium codebases */
*, *::before, *::after {
  box-sizing: border-box;
}
```

With `box-sizing: border-box`, an element given `width: 300px; padding: 24px; border: 2px solid #000;` remains exactly `300px` wide. Under legacy `content-box`, it would expand to `352px`, causing unexpected overflow.

## Modern Layouts: Flexbox vs. CSS Grid

### Flexbox Patterns (1-Dimensional Layouts)

Flexbox excels at distributing space along a single axis (row or column).

#### Centering a Child (Absolute Center)
```css
.center-box {
  display: flex;
  justify-content: center; /* Main axis */
  align-items: center;     /* Cross axis */
  min-height: 240px;
}
```

#### Application Navigation Bar with Spacer
```html
<header class="navbar">
  <div class="logo">Nexium Media</div>
  <nav class="nav-links">...</nav>
  <div class="user-profile">Profile</div>
</header>
```
```css
.navbar {
  display: flex;
  align-items: center;
  gap: 1.5rem;
  padding: 1rem 2rem;
}
.nav-links {
  margin-left: auto; /* Pushes navigation links and profile to the right edge */
  display: flex;
  gap: 1rem;
}
```

### CSS Grid Patterns (2-Dimensional Layouts)

CSS Grid controls rows and columns simultaneously.

#### Responsive Auto-Fitting Card Grid (No Media Queries Required)
```css
.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 320px), 1fr));
  gap: 1.5rem;
}
```

#### Full Page Application Layout
```css
.app-shell {
  display: grid;
  grid-template-rows: auto 1fr auto;
  grid-template-columns: 280px 1fr;
  grid-template-areas:
    "header  header"
    "sidebar main"
    "footer  footer";
  min-height: 100vh;
}

.site-header { grid-area: header; }
.site-sidebar { grid-area: sidebar; }
.site-main    { grid-area: main; }
.site-footer  { grid-area: footer; }

@media (max-width: 768px) {
  .app-shell {
    grid-template-columns: 1fr;
    grid-template-areas:
      "header"
      "main"
      "footer";
  }
  .site-sidebar { display: none; }
}
```

## CSS Custom Properties (Design Tokens)

CSS variables provide real-time runtime theming without stylesheet recalculation or JavaScript injection:

```css
:root {
  --font-sans: 'Inter', -apple-system, BlinkMacSystemFont, sans-serif;
  --color-brand-primary: #2563eb;
  --color-surface: #ffffff;
  --color-text-body: #1e293b;
  --radius-md: 0.5rem;
  --transition-fast: 150ms cubic-bezier(0.4, 0, 0.2, 1);
}

.dark {
  --color-surface: #0f172a;
  --color-text-body: #f8fafc;
}

.card {
  background-color: var(--color-surface);
  color: var(--color-text-body);
  border-radius: var(--radius-md);
  transition: background-color var(--transition-fast);
}
```

## Units & Fluid Sizing

- **`rem` (Root EM)**: Scales relative to the document root font size (`1rem = 16px` standard). Mandatory for font sizes, margins, and padding to respect user browser font scaling settings.
- **`em`**: Scales relative to the parent font size. Reserved for component-internal typography offsets (e.g., icons sized proportionally to adjacent button text).
- **`clamp(min, preferred, max)`**: Eliminates stepped media query jumps by enabling fluid scaling:

```css
/* Fluid typography: scales smoothly between 1.25rem (20px) and 2.5rem (40px) */
h1 {
  font-size: clamp(1.25rem, 0.75rem + 2.5vw, 2.5rem);
  line-height: 1.15;
}
```

## Pseudo-Classes & Pseudo-Elements

```css
/* Visible keyboard focus indicators - Mandatory for WCAG 2.1 AA */
button:focus-visible {
  outline: 2px solid var(--color-brand-primary);
  outline-offset: 2px;
}

/* Hide default outline only if focus is from pointer devices */
button:focus:not(:focus-visible) {
  outline: none;
}

/* Disabled state styling */
button:disabled {
  opacity: 0.5;
  cursor: not-allowed;
  pointer-events: none;
}

/* External link indicator using ::after */
a[target="_blank"]::after {
  content: " ↗";
  font-size: 0.85em;
  opacity: 0.75;
}
```

## CSS Specificity & `@layer`

CSS specificity determines which declaration applies when multiple rules match an element:

1. **Inline styles**: `style="..."` (1,0,0,0)
2. **IDs**: `#sidebar` (0,1,0,0)
3. **Classes, attributes, pseudo-classes**: `.btn`, `[type="text"]`, `:hover` (0,0,1,0)
4. **Elements and pseudo-elements**: `div`, `p`, `::before` (0,0,0,1)

### Cascade Layers (`@layer`)

Tailwind CSS organizes styles into explicit cascade layers:

```css
@layer base {
  h1 { font-size: 2rem; font-weight: 700; }
}

@layer components {
  .btn-primary {
    background-color: var(--color-brand-primary);
    padding: 0.5rem 1rem;
  }
}

@layer utilities {
  .text-red { color: #ef4444; }
}
```

Declarations in `@layer utilities` automatically override `@layer components` and `@layer base`, regardless of selector specificity.

## CSS Animations vs. JavaScript Animations

| Approach | When to Use | Performance Attributes |
| :--- | :--- | :--- |
| **CSS Transitions & `@keyframes`** | Hover states, fade-ins, dialog slide-ins, spinners. | Executed directly on GPU compositor thread (transforms, opacity). Zero JS bundle size. |
| **JavaScript (Framer Motion)** | Complex gesture tracking, physics springs, layout reordering, route exit transitions. | Runs on browser main thread; flexible programmatic interruption. |

<Callout type="note">
Always wrap visual animations in `@media (prefers-reduced-motion: reduce)` media queries to respect user OS accessibility preferences.
</Callout>

## Common Mistakes & Anti-Patterns

1. **Clickable `<div>` instead of `<button>`**: A `<div>` does not support Enter/Space keyboard triggers, receives no tab focus, and lacks screen reader role semantics.
2. **Missing `alt` on Images**: Decorative images must use `alt=""` or `role="presentation"`. Informational images must describe the content or function of the image.
3. **Overriding Outlines with `outline: none`**: Stripping focus outlines without a replacement leaves keyboard navigators blind. Always use `:focus-visible`.
4. **Pixel Units for Typography**: Setting `font-size: 14px` overrides user browser accessibility zoom settings. Always use `rem`.
