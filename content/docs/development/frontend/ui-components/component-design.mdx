Well-designed React components are intuitive to consume, resilient to change, and accessible by default. In a codebase shared by over 100 developers, adhering to consistent patterns for prop interfaces, ref forwarding, and DOM event mechanics prevents regressions and reduces onboarding time.

This guide details component design fundamentals, provides compound component architectures, and presents a complete, production-ready `Button` implementation with full unit test coverage.

## Anatomy of a Production-Ready Component

Every component authored for Nexium Media's shared component library must satisfy four baseline criteria:

1. **Clear Responsibility**: Focuses on a single semantic task.
2. **Explicitly Typed Props**: Fully typed interface extending native HTML attributes where applicable, documented via JSDoc.
3. **Accessible Markup**: Implements proper ARIA attributes, semantic tags, and keyboard focus states.
4. **Ref Forwarding & DevTools Support**: Uses `React.forwardRef` and explicit `displayName` assignments for DevTools visibility.

## Avoiding Boolean Traps

A common anti-pattern in React prop design is introducing multiple boolean flags to control mutually exclusive visual states:

```tsx
// Anti-Pattern: Boolean Traps create conflicting states
<Button isPrimary isSecondary isDanger isOutline /> // Invalid state combination!

// Best Practice: Discriminated Variant Prop
<Button variant="destructive" size="md" />
```

Use `variant` and `size` string unions backed by `class-variance-authority` (CVA). Reserve booleans strictly for independent binary toggles, such as `isLoading`, `disabled`, or `fullWidth`.

## Controlled vs. Uncontrolled Components

- **Controlled**: Form state is driven entirely by React props (`value`, `onChange`). The parent component serves as the single source of truth.
- **Uncontrolled**: Form state is held internally by the DOM (`defaultValue`). Values are accessed via refs or form submit events.

Shared library components should support controlled usage, while offering uncontrolled ergonomics through sensible default props or seamless React Hook Form integration.

## Compound Components Pattern

When a component consists of multiple coordinated elements (such as an Accordion, Dropdown, or Select menu), avoid passing deeply nested configuration arrays. Instead, use the **compound component pattern** with React Context:

```tsx
// Consuming a Compound Select Component
<Select value={selectedPlan} onValueChange={setSelectedPlan}>
  <Select.Trigger aria-label="Select Subscription Plan">
    <Select.Value placeholder="Choose a tier..." />
  </Select.Trigger>
  <Select.Content>
    <Select.Item value="starter">Starter Plan</Select.Item>
    <Select.Item value="pro">Professional Plan</Select.Item>
    <Select.Item value="enterprise">Enterprise Plan</Select.Item>
  </Select.Content>
</Select>
```

Compound components give consuming developers complete control over rendering order, accessibility relationships, and custom styling without requiring changes to the core component logic.

## Complete Production Example: The `Button` Primitive

Below is the canonical implementation of the Nexium `Button` primitive, combining `cva`, `forwardRef`, loading states, accessibility states, and JSDoc documentation:

```tsx
// components/ui/Button.tsx
import * as React from "react";
import { cva, type VariantProps } from "class-variance-authority";
import { clsx } from "clsx";
import { twMerge } from "tailwind-merge";

function cn(...inputs: (string | undefined | null | false)[]) {
  return twMerge(clsx(inputs));
}

export const buttonVariants = cva(
  "inline-flex items-center justify-center whitespace-nowrap rounded-md text-sm font-medium transition-colors focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-offset-2 disabled:pointer-events-none disabled:opacity-50 select-none",
  {
    variants: {
      variant: {
        primary: "bg-blue-600 text-white hover:bg-blue-700 focus-visible:ring-blue-600",
        secondary: "bg-slate-100 text-slate-900 hover:bg-slate-200 focus-visible:ring-slate-500",
        destructive: "bg-red-600 text-white hover:bg-red-700 focus-visible:ring-red-600",
        outline: "border border-slate-300 bg-transparent hover:bg-slate-50 focus-visible:ring-slate-400",
        ghost: "hover:bg-slate-100 text-slate-700 hover:text-slate-900",
      },
      size: {
        sm: "h-8 px-3 text-xs",
        md: "h-10 px-4 py-2",
        lg: "h-12 px-8 text-base",
        icon: "h-10 w-10 p-0",
      },
    },
    defaultVariants: {
      variant: "primary",
      size: "md",
    },
  }
);

export interface ButtonProps
  extends React.ButtonHTMLAttributes<HTMLButtonElement>,
    VariantProps<typeof buttonVariants> {
  /**
   * If true, displays an accessible inline SVG loading spinner and disables click actions.
   */
  isLoading?: boolean;
}

export const Button = React.forwardRef<HTMLButtonElement, ButtonProps>(
  ({ className, variant, size, isLoading = false, disabled, children, ...props }, ref) => {
    return (
      <button
        ref={ref}
        disabled={disabled || isLoading}
        aria-busy={isLoading}
        className={cn(buttonVariants({ variant, size, className }))}
        {...props}
      >
        {isLoading && (
          <svg
            className="mr-2 h-4 w-4 animate-spin text-current"
            xmlns="http://www.w3.org/2000/svg"
            fill="none"
            viewBox="0 0 24 24"
            aria-hidden="true"
          >
            <circle
              className="opacity-25"
              cx="12"
              cy="12"
              r="10"
              stroke="currentColor"
              strokeWidth="4"
            />
            <path
              className="opacity-75"
              fill="currentColor"
              d="M4 12a8 8 0 018-8V0C5.373 0 0 5.373 0 12h4zm2 5.291A7.962 7.962 0 014 12H0c0 3.042 1.135 5.824 3 7.938l3-2.647z"
            />
          </svg>
        )}
        {children}
      </button>
    );
  }
);

Button.displayName = "Button";
```

## Unit Test Suite for `Button`

Every shared component must include automated unit tests covering rendering, variants, states, and accessibility:

```tsx
// components/ui/Button.test.tsx
import * as React from "react";
import { render, screen } from "@testing-library/react";
import userEvent from "@testing-library/user-event";
import { Button } from "./Button";

describe("Button Component", () => {
  it("renders with default props and text content", () => {
    render(<Button>Click Me</Button>);
    const button = screen.getByRole("button", { name: /click me/i });
    expect(button).toBeInTheDocument();
    expect(button).toHaveClass("bg-blue-600"); // Primary variant
  });

  it("applies the destructive variant classes", () => {
    render(<Button variant="destructive">Delete Project</Button>);
    const button = screen.getByRole("button", { name: /delete project/i });
    expect(button).toHaveClass("bg-red-600");
  });

  it("disables the button and shows spinner when isLoading is true", () => {
    render(<Button isLoading>Submit</Button>);
    const button = screen.getByRole("button", { name: /submit/i });
    expect(button).toBeDisabled();
    expect(button).toHaveAttribute("aria-busy", "true");
  });

  it("triggers onClick handler when clicked by a user", async () => {
    const handleClick = jest.fn();
    const user = userEvent.setup();

    render(<Button onClick={handleClick}>Trigger Action</Button>);
    const button = screen.getByRole("button", { name: /trigger action/i });

    await user.click(button);
    expect(handleClick).toHaveBeenCalledTimes(1);
  });

  it("prevents click handler execution when disabled", async () => {
    const handleClick = jest.fn();
    const user = userEvent.setup();

    render(<Button disabled onClick={handleClick}>Disabled</Button>);
    const button = screen.getByRole("button", { name: /disabled/i });

    await user.click(button);
    expect(handleClick).not.toHaveBeenCalled();
  });
});
```

<Callout type="tip">
Always run tests using `@testing-library/user-event` rather than `fireEvent`. `userEvent` faithfully replicates full browser pointer and focus events, ensuring high-fidelity test assertions.
</Callout>
